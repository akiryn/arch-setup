# 与桌面相关的应用启动流程
以我当前情况为例,主机为Fedora+dms greeter+niri+dms

当前的图形登录由 **greetd + DMS Greeter + niri + PAM** 配合完成

## 系统核心组件启动
```
固件 → 引导程序 → Linux 内核 → systemd（PID 1）
```

| 系统组件             | 为桌面提供什么        |
| ---------------- | -------------- |
| `systemd-udevd`  | 发现和管理设备        |
| `systemd-logind` | 管理登录会话、座席和设备访问 |
| `系统 D-Bus`       | 让程序与系统服务通信     |
| `NetworkManager` | 网络连接           |
| `bluetoothd`     | 蓝牙             |
| `greetd`         | 登录管理           |
这些服务大多并行启动，并不是严格一条线依次执行。语言方面，系统配置是：
```ini
# /etc/locale.conf
LANG="en_US.UTF-8"
```

此外系统启动通常由服务依赖或 socket 激活机制触发，**不是 PID 1 按固定顺序写死地逐个调用这些程序**。systemd 根据 unit 配置判断什么时候需要启动它们。

另外，你机器上还有一套**用户 D-Bus**，由用户级 systemd 管理：

```
系统 systemd（PID 1）
└─ systemd --user（用户 y，PID 1407）
   └─ dbus-broker-launch（PID 1536）
      └─ dbus-broker（PID 1537）
```

两套总线用途不同：

- **系统 D-Bus**：供应用与 NetworkManager、蓝牙、logind 等系统服务通信。
- **用户 D-Bus**：供当前用户的桌面应用、通知服务、portal 等通信。

“系统 D-Bus”指的是系统范围的通信总线，**不表示总线进程必须以 root 身份运行**；你这台机器上它使用专门的 `dbus` 用户。
## 登录页面启动
greetd 启动一个专门用于登录的小型图形会话
本机 `/etc/greetd/config.toml` 配置的命令是：
```toml
[terminal]
vt = 1

[default_session]
command = "/usr/bin/dms-greeter --command niri --cache-dir /var/cache/dms-greeter -C /etc/greetd/niri/config.kdl"
user = "greeter"
```
这表示：

- 登录界面运行在 **第 1 个虚拟终端**。
- greetd 以专用账户 **`greeter`** 启动 `dms-greeter`。
- 登录界面的合成器使用 **niri**，读取 `/etc/greetd/niri/config.kdl`。
- 该配置包含 `DMS_RUN_GREETER="1"`，用于登录界面模式。
运行身份是 `greeter`。

这里各自的职责是：

- **greetd**：管理登录过程，通过 PAM 完成身份认证、建立用户会话。
- **dms-greeter**：提供你看到的图形登录界面。
- **登录界面用的 niri**：给登录界面提供 Wayland 显示环境。
**登录时的 niri 和登录后的 niri，是不同用途、不同用户身份的实例。** 前者使用 `/etc/greetd/niri/` 中的配置，后者使用你的用户配置。
因此，你用户目录里的 `LANGUAGE` 设置，也不能直接解释登录界面的语言——登录界面属于 `greeter` 用户的环境。
输入密码验证成功后进入启动流程(通过一个脚本调动)
启动流程:
```
开机
  ↓
系统 systemd（PID 1）启动
  ↓
启动 greetd
  ↓
显示登录界面
  ↓
你输入账号密码，PAM 验证通过
  ↓
PAM 建立用户会话
  ↓
pam_systemd 与 systemd-logind 协作注册会话
  ↓
系统 systemd 启动 user@1000.service
  ↓
你的 systemd --user 启动
  ↓
读取用户环境配置，包括 environment.d 中的 LANGUAGE
  ↓
greetd 启动你的会话入口 niri-session
  ↓
niri-session 请求 systemd --user 启动 niri.service
  ↓
进入桌面
```


`niri-session` 是 niri 提供的“桌面会话启动脚本”(本质为一个脚本)。安装登录界面后，它仍然承担原来的工作，只是从你手动执行，变成登录管理器替你执行。
```
TTY 登录
   ↓
你的 shell
   ↓ 手动输入 niri-session
niri-session
   ↓ 请求 systemd 用户服务启动
niri --session
   ↓
进入桌面
```
因此流程变成：

```
greetd + 图形登录界面
   ↓ 完成认证，选择 Niri 会话
niri-session
   ↓ 请求 systemd 用户服务启动
niri --session
   ↓
进入桌面
```

**登录界面解决“谁登录、启动哪个会话”；`niri-session` 解决“怎样把 niri 会话正确启动并收尾”。**

| 阶段               | `niri-session` 的工作                              |                         |
| ---------------- | ----------------------------------------------- | ----------------------- |
| 准备环境             | 通过登录 shell 执行会话启动流程，使登录 shell 配置有机会生效           |                         |
| 防止重复             | 检查 `niri.service` 是否已经运行                        |                         |
| 同步环境             | 将登录环境导入 systemd 用户服务管理器及 D-Bus 激活环境             |                         |
| 启动桌面             | 执行 `systemctl --user --wait start niri.service` |                         |
| 等待退出             | 保持等待，直到 niri 会话结束                               |                         |
| 清理会话             | 启动 `niri-shutdown.target`，清除显示连接等会话环境变量         |                         |
| 名称               | 是什么                                             | 职责                      |
| `niri-session`   | 启动脚本                                            | 准备、启动、等待、清理整个会话         |
| `niri.service`   | systemd 服务定义                                    | 告诉 systemd 如何管理 niri 进程 |
| `niri --session` | 真正运行的合成器进程                                      | 提供窗口、显示、输入管理，并启用会话集成    |


用户服务管理器的环境生成器读取：
```ini
# ~/.config/environment.d/locale.conf
LANGUAGE=zh_CN:en_US
```
于是，准备传给用户服务的环境包含：
```
LANG=en_US.UTF-8
LANGUAGE=zh_CN:en_US
```

## 进入桌面后
```
systemd --user
   ├─ niri
   └─ dms
       └─ qs
```
DMS 和 niri 是协作关系，DMS 由 systemd 启动；它再把自己的界面交给 niri 显示。niri 本身不提供完整桌面环境，需要以下配套组件共同工作。

| 本机组件                              | 主要职责                  | 本机启动方式或关系                            |
| --------------------------------- | --------------------- | ------------------------------------ |
| DMS / `qs`                        | 桌面面板、通知、控制界面等         | `dms.service`                        |
| `fcitx5`                          | 输入法                   | niri 配置的 `spawn-at-startup "fcitx5"` |
| `PipeWire`                        | 音视频流处理                | 用户服务及 socket 激活机制                    |
| `WirePlumber`                     | 音频设备、路由和策略管理          | 与 PipeWire 服务关联                      |
| `pipewire-pulse`                  | 兼容使用 PulseAudio 接口的应用 | 用户服务及 socket                         |
| `xdg-desktop-portal` 及后端          | 文件选择、屏幕共享等桌面接口        | 用户服务，支持按需激活                          |
| `dbus-broker`                     | 用户会话内的消息通信            | 用户 D-Bus 服务                          |
| `gnome-keyring`                   | 保存密码和秘密数据             | 登录集成或服务激活                            |
| GVfs                              | 桌面文件访问、卷和网络位置等支持      | 用户服务和按需启动                            |
| `xwayland-satellite` → `Xwayland` | 让 X11 应用接入 niri 桌面    | 已确认是 niri 下的进程链                      |
这些组件不一定全在同一时刻启动。有些随桌面启动，有些在应用第一次请求功能时才启动。

```
固件 → 引导 → Linux 内核 → 系统 systemd
                              │
                              ├─ 系统服务：网络、蓝牙、logind、系统 D-Bus
                              │
                              ├─ greetd
                              │    ├─ 登录界面：dms-greeter + 登录用 niri
                              │    └─ 登录成功 → niri-session
                              │                        │ 请求启动
                              └─ systemd --user ←──────┘
                                   │
                  environment.d ──→│ LANG / LANGUAGE
                                   │
                                   ├─ niri：显示、输入、窗口管理
                                   │    ├─ fcitx5
                                   │    ├─ Xwayland 支持
                                   │    └─ 快捷键启动终端、启动器
                                   │
                                   ├─ DMS → qs：桌面界面
                                   ├─ PipeWire / WirePlumber：音频
                                   ├─ portals：桌面接口
                                   └─ D-Bus、密钥环、GVfs 等
```

 - `systemd PID 1` 管理整机服务如网络、登录管理器等
 - `systemd --user` 管理用户服务如niri、DMS、音频等
 - `greetd` 登录管理器后台：启动登录界面、协调认证、启动用户会话
 - `DMS Greeter` 看到的登录界面，负责与用户交互





# 桌面启动流程

本文以 Fedora 上的 greetd、DankGreeter、niri 和 DankMaterialShell（DMS）组合为例，介绍从系统启动到进入桌面的过程，以及环境变量如何传递给应用。


## 组件职责

| 组件                         | 职责                       |
| -------------------------- | ------------------------ |
| 系统 systemd（PID 1）          | 管理系统服务及其依赖               |
| systemd-logind             | 管理登录会话、座席与设备访问           |
| PAM                        | 按服务配置执行认证与会话建立等操作        |
| greetd                     | 启动 Greeter，协调认证并启动所选用户会话 |
| DankGreeter（dms-greeter）   | 提供登录界面                   |
| 用户 systemd（systemd --user） | 管理该用户的服务和服务启动环境          |
| niri                       | Wayland 合成器，管理显示、输入和窗口   |
| DMS                        | 提供面板、启动器、通知和其他桌面界面       |
| Quickshell（qs）             | 运行 DMS 的 QML 界面          |

DankGreeter 提供登录前的认证界面，DMS 锁屏则保护已经运行的用户会话。两者处于不同阶段。

## 从开机到登录界面

```text
固件 → 引导程序 → Linux 内核 → 系统 systemd
                                  ├─ 设备、网络等系统服务
                                  ├─ systemd-logind、系统 D-Bus
                                  └─ greetd → DankGreeter + 登录界面用的 niri
```

以下为参考环境中 `/etc/greetd/config.toml` 的关键配置片段。运行账户、虚拟终端和配置路径应与实际安装方式一致。

```toml
[terminal]
vt = 1

[default_session]
command = "/usr/bin/dms-greeter --command niri --cache-dir /var/cache/dms-greeter -C /etc/greetd/niri/config.kdl"
user = "greeter"
```

- `vt = 1` 指定登录界面使用的虚拟终端。
- `user = "greeter"` 指定登录界面的运行账户。
- `--command niri` 指定登录界面使用的合成器。
- `-C` 指向登录界面用的 niri 配置。

登录界面中的 niri 和登录后运行的 niri 是不同实例，使用不同身份和配置。普通用户的语言环境不会自动成为 `greeter` 用户的语言环境。DankGreeter 的部署方式与参数应以对应版本的[官方安装文档](https://danklinux.com/docs/dankgreeter/installation)为准。

## 从登录到用户桌面

参考环境中的 Niri 会话文件 `/usr/share/wayland-sessions/niri.desktop` 使用 `Exec=niri-session` 指定启动入口，对应脚本为 `/usr/bin/niri-session`。选择该会话后，主要流程如下：

```text
greetd 完成认证并建立用户会话
  ↓
启动所选会话入口 niri-session
  ↓
准备登录环境，将环境导入用户服务管理器和 D-Bus 激活环境
  ↓
请求 systemd --user 启动 niri.service
  ↓
niri --session 运行，建立图形会话集成
  ↓
已配置的 DMS 等桌面服务启动，应用可以连接显示服务
```

### niri-session、niri.service 和 niri --session

| 名称 | 类型 | 作用 |
| --- | --- | --- |
| `niri-session` | 会话启动脚本 | 协调环境准备、服务启动、等待退出和清理 |
| `niri.service` | systemd 用户服务定义 | 描述如何启动及管理合成器 |
| `niri --session` | 合成器进程及其启动参数 | 运行 niri 并启用会话集成 |

脚本在常规 systemd 启动分支中，会经过登录 Shell、检查重复会话、导入环境，并执行 `systemctl --user --wait start niri.service`。会话结束后启动 `niri-shutdown.target`，再清除显示连接等会话变量。

TTY 手动启动与图形登录可以使用同一入口：前者由登录 Shell 执行 `niri-session`，后者由登录管理器启动所选会话。手动启动适用于尚未运行图形会话的情形。

## 桌面组件如何启动

参考环境中，`niri.service` 的 `ExecStart` 是 `niri --session`，与 `graphical-session.target` 关联。`dms.service` 的 `ExecStart` 是 `dms run --session`，同样关联到图形会话，并配置了失败后重启。

```text
用户服务管理器
  ├─ niri.service → niri --session
  ├─ dms.service → dms → Quickshell 界面
  └─ 音频、portal 等用户服务
```

这表示服务管理关系，不表示所有程序都由 niri 直接创建。DMS 在其他安装方式中也可能通过合成器的启动配置运行，应根据实际安装方式检查启动关系。

| 配套组件 | 用途 | 常见启动途径 |
| --- | --- | --- |
| Fcitx5 | 输入法框架 | 合成器启动配置或桌面自启动项，避免重复启动 |
| PipeWire、WirePlumber | 音视频处理与设备策略 | 用户服务、socket 激活 |
| xdg-desktop-portal 及后端 | 文件选择、屏幕共享等桌面接口 | D-Bus 激活和用户服务 |
| 密钥环服务 | 保存和访问凭据 | PAM 集成或按需激活，取决于安装配置 |
| GVfs | 桌面文件访问与网络位置 | 按需激活 |
| xwayland-satellite | 支持 X11 应用 | 取决于 niri 版本与配置 |

上表概括各组件的职责和常见启动方式。具体依赖可参考 niri 的[配套软件说明](https://niri-wm.github.io/niri/Important-Software.html)。

## 环境变量如何传递给应用

`environment.d` 是 systemd 用户服务环境机制，并非 niri 专用配置。默认用户配置目录是 `~/.config/environment.d/`；使用自定义 `XDG_CONFIG_HOME` 时，该变量必须在环境生成器确定目录之前就已可用。

```text
用户 environment.d/*.conf
  ↓ 用户环境生成器读取
systemd --user 提供给新服务的环境
  ├─ niri.service → niri 启动的程序
  └─ dms.service → DMS 启动的程序（具体路径依启动实现而定）
```

需要区分三个层次：

1. **配置文件**表达希望设置的值。
2. **用户服务管理器环境**决定新启动服务可以获得的值。
3. **具体进程环境**是该进程启动时继承或自行修改后的值。

会话脚本导入的登录环境、服务自己的 `Environment=` 和应用内部设置也可能影响最终结果。修改文件不会自动改变已经运行的程序；通过 D-Bus 或其他服务间接启动的应用也不一定沿用当前终端的环境。

配置格式及加载规则可通过 `man environment.d` 查看，也可查阅 [systemd 官方手册](https://www.freedesktop.org/software/systemd/man/latest/environment.d.html)。语言变量的含义、配置和检查见[中文环境配置](中文环境配置.md)。

### 系统 D-Bus 与用户 D-Bus

- **系统 D-Bus**用于访问 NetworkManager、logind 等系统服务。
- **用户 D-Bus**用于桌面应用、通知和用户服务之间的通信。

“系统总线”描述其作用范围，不意味着总线进程一定由 root 运行。D-Bus 的服务激活环境与 systemd 用户服务环境需要区分；参考版本的 `niri-session` 会分别处理这两类环境的导入。

## 只读检查方法

以下命令在当前图形会话的终端中执行，不加 sudo，不会修改服务状态。

```bash
systemctl status greetd --no-pager
systemctl --user status niri.service dms.service --no-pager
systemctl --user cat niri.service dms.service
```

预期：使用本文启动方式的机器上，niri 与 DMS 服务处于 `active`，服务定义的启动命令与安装方式相符。若提示找不到单元，应先确认该组件是否通过其他方式启动。

只查看语言相关环境，避免输出整个环境中的敏感值：

```bash
systemctl --user show-environment | grep -E '^(LANG|LANGUAGE|LC_[A-Z_]+)='
```

排查本次开机的服务错误：

```bash
journalctl --user -b -u niri.service -u dms.service --no-pager -n 80
```

分享日志前应检查其中的应用路径和个人信息。以上命令均为只读检查。

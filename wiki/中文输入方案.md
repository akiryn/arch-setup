# Arch Linux 中文输入方案

本文以 Niri 上的 **Fcitx5 + Rime + 雾凇拼音** 为例。装好后可使用雾凇全拼，并按需启用小鹤双拼、万象语法模型和 AI 联想。

如果你使用 GNOME，可以优先考虑桌面集成的 IBus。本文的启动方式和兼容性设置针对 Fcitx5，其他桌面请结合自己的会话配置。

## 安装并验证基础输入
### 安装 Fcitx5、Rime 和雾凇拼音

```bash
sudo pacman -Syu fcitx5-im fcitx5-rime rime-ice-git
```

`fcitx5-im` 是软件包组，包含 Fcitx5、图形配置工具，以及 GTK 和 Qt 输入法模块。`fcitx5-rime` 将 Rime 接入 Fcitx5，`rime-ice-git` 提供雾凇拼音方案。

 `rime-ice-git` 来自 `archlinuxcn`。如果 Pacman 提示找不到软件包，请先确认软件源或查看雾凇拼音项目的安装说明。
### 在 Niri 中启动 Fcitx5

如果会话还没有启动 Fcitx5，可在 `~/.config/niri/config.kdl` 的顶层加入：

```kdl
spawn-at-startup "fcitx5" "-d"
```

每次登录 Niri 时会自动启动。当前会话若还没运行 Fcitx5，可以在终端执行 `fcitx5 -d`。

打开 `fcitx5-configtool`，在「输入法」页确认当前组包含 **Rime**。需要单独切回英文键盘时，可以同时保留 **Keyboard - English (US)**。

### 选择 Rime 输入方案

编辑 `~/.local/share/fcitx5/rime/default.custom.yaml`。目录不存在时先执行：

```bash
mkdir -p ~/.local/share/fcitx5/rime
```

下面是一个方案列表示例：

```yaml
patch:
  __include: rime_ice_suggestion:/
  schema_list:
    - schema: luna_pinyin_simp
    - schema: rime_ice
    - schema: bopomofo
    - schema: double_pinyin_flypy
```

`rime_ice` 是雾凇全拼，`double_pinyin_flypy` 是小鹤双拼。只保留你想用且已安装的方案。`__include` 引用雾凇的建议预设，使用这行前应确认该预设随方案一起安装。

> 如果文件已有 `patch:`，把设置合并到原有的 `patch:` 下，避免出现两个同名的顶层键，也避免覆盖其他自定义项。

保存后，在 Fcitx5 托盘的 Rime 菜单中选择 **重新部署**。切换到雾凇拼音，在文本框输入 `nihao`，确认能看到候选并选词上屏。

## 日常定制

### 添加自定义短语

自定义短语适合添加人名、专有名词和常用句子。全拼和双拼可以分别设置自己的触发编码。

| 方案 | Rime 用户目录中的文件 |
| --- | --- |
| 雾凇全拼 `rime_ice` | `custom_phrase.txt` |
| 小鹤双拼 `double_pinyin_flypy` | `custom_phrase_double.txt` |

文件位于 `~/.local/share/fcitx5/rime/`。文件不存在时可新建，已存在时追加。每行使用 **候选文字、Tab、触发编码**，可再用一个 Tab 添加权重。

```text
明日方舟	mrfz
Niri	niri
```


### 统一左右 Shift 的中英文切换

Fcitx5 可以切换输入法，Rime 也可以在当前方案内部切换 ASCII 模式。如果左右 Shift 分别操作这两层，就可能遇到切到英文后无法用另一个 Shift 切回中文的情况。

如果希望左右 Shift 都由 Fcitx5 处理，在 Fcitx5 配置工具里将它们设为替代触发键。手动编辑 `~/.config/fcitx5/config` 时，对应配置段如下：

```ini
[Hotkey/AltTriggerKeys]
0=Shift_L
1=Shift_R
```

再把下面两项合并到 `default.custom.yaml` 的 `patch:` 中，关闭 Rime 对单按 Shift 的内部切换动作：

```yaml
patch:
  "ascii_composer/switch_key/Shift_L": noop
  "ascii_composer/switch_key/Shift_R": noop
```

保存后重新部署 Rime。若手动编辑了 Fcitx5 配置，还需让 Fcitx5 重新加载设置。最后分别测试左右 Shift 和原有的输入法切换键。

### 更换候选框主题

Fcitx5 主题主要改变候选框的颜色、间距和圆角。以 [Catppuccin Fcitx5](https://github.com/catppuccin/fcitx5) 为例，按项目说明将所选主题目录安装到 `~/.local/share/fcitx5/themes/`。

然后在 `fcitx5-configtool` 中打开「附加组件 → 经典用户界面」，选择主题。

## 可选增强

### 接入万象语法模型

万象语法模型可用于辅助 Rime 的整句候选排序。

```bash
sudo pacman -Syu rime-wanxiang-gram-zh-hans
```

将下面的设置合并到 `~/.local/share/fcitx5/rime/rime_ice.custom.yaml` 的 `patch:` 下：

```yaml
patch:
  "grammar/language": wanxiang-lts-zh-hans
```

保存并重新部署。

### 接入 AI 联想和翻译

[rime-llm-translator](https://github.com/SHORiN-KiWATA/rime-llm-translator) 可以在显式触发后，将当前输入交给所选模型处理。按项目说明配置 API 或 CLI 后端，再确认全拼和双拼的触发键。

插件的自定义词库用于 AI 请求。想让短语在日常候选栏中出现，请使用前面的 `custom_phrase*.txt`。

## Wayland 兼容性与排障

先确认问题发生在所有应用，还是某一个应用。所有应用都无法输入时，优先检查 Fcitx5 是否运行、当前输入法组是否包含 Rime，以及 Rime 是否已成功部署。只有某个应用有问题时，再检查它的 GUI 工具包、运行后端和输入法接入方式。

### 按应用类型排查

| 应用类型 | 优先检查 |
| --- | --- |
| 原生 Wayland 的 GTK 3 / GTK 4 | 优先尝试原生 Wayland 输入法协议，异常时再单独测试 Fcitx5 GTK 模块 |
| Qt 应用 | 确认已装 `fcitx5-qt`。可对问题应用单独测试 `QT_IM_MODULE=fcitx` |
| XWayland 应用 | 确认应用通过 GTK／Qt 模块或 XIM 接入。需要 XIM 时检查 `XMODIFIERS=@im=fcitx` |
| Chromium / Electron | 先确认运行于原生 Wayland 还是 XWayland，再按对应版本的文档配置输入法参数 |
| SDL 游戏或多媒体应用 | 先确认 SDL 版本和显示后端。遇到输入问题时再测试 `SDL_IM_MODULE=fcitx` |

例如，测试某个 Qt 应用是否能通过 Fcitx5 模块输入：

```bash
QT_IM_MODULE=fcitx 应用命令
```

较新的 Qt 可使用 `QT_IM_MODULES` 指定候选模块，例如 `wayland;fcitx`。具体可用性取决于 Qt 版本。若把变量写入 `~/.config/environment.d/`，修改后应重新登录，并确认目标应用进程实际继承了它。

对于仍需使用 Fcitx5 GTK 模块的旧应用，可以先按应用测试 `GTK_IM_MODULE=fcitx`。确实需要长期配置时，GTK 2 的用户配置在 `~/.gtkrc-2.0`，GTK 3 和 GTK 4 的设置分别在 `~/.config/gtk-3.0/settings.ini` 和 `~/.config/gtk-4.0/settings.ini`。设置 GTK 3 或 GTK 4 时，将 `gtk-im-module=fcitx` 加入已有的 `[Settings]` 段。修改后重启目标应用，检查候选框位置和输入行为。

可以运行 `fcitx5-diagnose` 收集诊断信息。Wayland 与 XWayland 的详细设置以 Fcitx5 官方文档为准。


```bash
mkdir -p ~/.config/environment.d/
vim ~/.config/environment.d/rime.conf
```
写入
```conf
XMODIFIERS=@im=fcitx
QT_IM_MODULES="wayland;fcitx"
QT_IM_MODULE=fcitx
SDL_IM_MODULE=fcitx
```

然后是 Electron 和 GTK 应用的设置

```
# 编辑 gtk2.0 的配置文件，让 XWayland 运行的 GTK2.0 应用走 GTK 的输入法模块
vim ~/.gtkrc-2.0
```

写入：

```
gtk-im-module="fcitx"
```

然后是 GTK3.0 和 4.0 的配置文件，以 XWayland 运行的时候走 GTK 的输入法模块

```
mkdir -p ~/.config/gtk-3.0
vim ~/.config/gtk-3.0/settings.ini
```

```
[Settings]
gtk-im-module=fcitx
```

```
mkdir -p ~/.config/gtk-4.0
vim ~/.config/gtk-4.0/settings.ini
```

```
[Settings]
gtk-im-module=fcitx
```

之所以在配置文件中写而不是在设置环境变量的地方写，是因为环境变量优先级最高，如果以 Wayland 运行的 GTK 软件被设置了 GTK 的输入法模块环境变量，可能会出现闪烁、错位、无法输入等异常。而写在 GTK 配置文件中的内容优先级是最低的，当软件以 Wayland 运行时这些设置会被代码中硬编码的回退值覆盖，所以这些设置对以 Wayland 运行的 GTK 软件不生效，由此避免了异常。

## 延伸阅读：Linux 中文输入是怎么工作的

在编辑器里敲下 `nihao`，选中「你好」并上屏，背后涉及两件事。**Rime 要理解你敲的编码，应用也要能接收输入法提交的文字。** 前者由输入引擎和方案决定，后者取决于应用如何接入输入法。

### Fcitx5、Rime 和雾凇拼音的分工

| 名称                    | 所属层次         | 职责                                |
| --------------------- | ------------ | --------------------------------- |
| Fcitx5                | 输入法框架        | 管理输入法组、启用状态和切换热键，协调输入引擎、候选窗口与文字提交 |
| Rime                  | 输入引擎         | 维护输入状态，解析编码、查词、生成和排序候选，并按方案处理选词   |
| 雾凇拼音                  | Rime 方案及配套数据 | 提供拼音规则、词典、标点和候选处理配置               |
| 万象语法模型                | 可选的语言模型数据    | 在方案启用后参与整句候选的评分和排序                |
| `rime-llm-translator` | 可选的 Rime 扩展  | 在触发 AI 功能时调用配置的模型后端，并将结果交回输入法     |

```
编辑器输入nihao -> Fcitx5框架管理输入状态将按键交给Rime -> Rime输入引擎解析拼音并查找生成候选词 -> 雾凇拼音输入方案提供拼音规则、词条、词库等数据供Rime输入引擎调用
```
`fcitx5-rime` 把 Rime 接入 Fcitx5。在 Fcitx5 里选择的是 **Rime 输入法**，在 Rime 的方案菜单里选择的是**雾凇全拼或小鹤双拼**。两个菜单分别管理框架和引擎内部的设置。

以雾凇全拼输入「你好」为例：

1. 文本框获得焦点后，应用和输入法通过当前会话所用的接口建立输入上下文。
2. Fcitx5 将相关按键交给 Rime。Rime 按雾凇的规则解析 `nihao`，查询词典并生成候选。
3. 输入过程中，应用可能显示尚未确认的**预编辑文本**，例如带下划线的拼音。同时，输入法界面可以显示候选列表。
4. 按空格选中首选候选后，输入法把「你好」作为已确认的文字提交给应用。

预编辑、候选框和文字上屏属于不同环节。例如，候选框能正常弹出却跟不上光标，排查重点通常在光标位置传递和界面定位。如果选词后文字没有进入文本框，则应进一步检查提交路径。

### 应用连接 Fcitx5 的三条常见路径

应用使用 GTK、Qt 或 Electron 等技术提供界面。工具包或应用框架的版本、显示后端和配置，都会影响它怎样接入输入法。同一台 Niri 桌面上，下面三条路径可以共存。

#### 原生 Wayland 输入法协议

```text
应用的文本输入组件
    ↕ text-input
Niri 合成器
    ↕ input-method
Fcitx5
    ↕
Rime
```

`text-input` 连接应用和合成器，协调用于文本输入的状态及事件，例如输入框激活、光标矩形、预编辑和文字提交。`input-method` 连接合成器和输入法，让输入法能与该输入上下文交互。

应用、合成器和输入法需要支持相应的协议及版本。应用能够在原生 Wayland 下显示窗口，只说明显示后端可以工作。原生输入法还需要应用具备兼容的文本输入实现。

#### GTK 或 Qt 输入法模块

```text
GTK / Qt 应用
    ↕ 工具包输入法接口
Fcitx5 GTK / Qt 模块
    ↕ 通常通过 D-Bus 通信
Fcitx5
    ↕
Rime
```

工具包加载输入法模块后，由模块把应用的输入上下文接到 Fcitx5，再将预编辑或已提交的文字交回应用。

**窗口显示后端和输入法接入方式可以分别选择。** 一个 GTK 应用可以用原生 Wayland 显示窗口，同时通过 Fcitx5 GTK 模块使用输入法。调整 `GTK_IM_MODULE` 或 `QT_IM_MODULE`，影响的是工具包选择的输入法模块。

#### XIM

```text
使用 XIM 的 X11 应用
    ↕ XIM
Fcitx5 的 XIM 前端
    ↕
Rime
```

XIM 是 X11 的输入法协议。在 Niri 会话中，经 XWayland 运行的 X11 应用也可能使用它。`XMODIFIERS=@im=fcitx` 用于让这类客户端选择 Fcitx。

XWayland 负责让 X11 应用在 Wayland 会话中运行。应用的输入法既可以走 XIM，也可以走 GTK 或 Qt 输入法模块，具体取决于应用和工具包的选择。

### 为什么同一个应用换后端，中文输入表现也会变

以 VS Code、Obsidian 等 Electron 应用为例。Electron 使用 Chromium 的 Ozone 平台层，窗口可以走两条显示路径：

```text
原生 Wayland：Electron → Chromium / Ozone Wayland → Niri
XWayland：    Electron → Chromium / Ozone X11 → XWayland → Niri
```

原生 Wayland 模式下，支持相应文本输入协议的应用可以通过 Niri 接入输入法。XWayland 模式下，应用使用它支持的 X11 输入法接入方式。切换显示后端后，输入法路径也可能随之变化，从而影响候选框定位、预编辑和选词上屏。

| 应用技术 | 排查时应确认什么 |
| --- | --- |
| GTK 3 / GTK 4 | GDK 使用 Wayland 还是 X11 后端，输入法走原生协议还是 GTK 模块 |
| Qt 5 / Qt 6 | Qt 使用 Wayland 还是 XCB 后端，以及该版本支持的文本输入协议和 Qt 输入法模块 |
| Chromium / Electron | Ozone 实际选了哪个后端，以及当前版本如何接入输入法 |
| Tauri | Linux 上使用的 WebKitGTK、GTK 版本和应用实际运行后端 |
| wxWidgets / Flutter | 应用使用的 Linux 工具包或嵌入器，以及它的文本输入集成方式 |

如果其他应用可以正常输入，Fcitx5 和 Rime 已经至少在一条路径上工作。此时，检查出问题的应用比重新配置整套输入法更容易定位故障。

### SDL 游戏和多媒体应用的文本输入

SDL 是跨平台多媒体库，提供窗口、键盘、鼠标、图形和音频等接口。使用 SDL 的程序可以通过 X11 或 Wayland 后端运行，中文输入还取决于 SDL 版本和程序对文本输入的集成。

以游戏为例，按 `W` 移动角色通常是**按键事件**。在聊天框里输入「你好」则是**文本输入事件**。游戏可以分别处理这两类事件，所以测试输入法时，应先打开聊天框、搜索框或存档命名框等实际接收文字的界面。

如果只有某个 SDL 应用有问题，先确认它的版本和显示后端，再判断是否需要按应用测试 `SDL_IM_MODULE=fcitx`。

### 为什么左右 Shift 都能切英文，却有时切不回来

| 切换层次     | 状态变化                            | 回到中文的方式                |
| -------- | ------------------------------- | ---------------------- |
| Fcitx5 层 | 切到英文键盘输入法，或停用当前输入法，取决于输入法组和热键设置 | 用 Fcitx5 热键回到已启用的 Rime |
| Rime 层   | 当前仍使用 Rime，但方案启用了 ASCII 模式      | 在 Rime 内关闭 ASCII 模式    |

例如，右 Shift 先把 Rime 切到 ASCII 模式，左 Shift 再让 Fcitx5 切到英文键盘。之后按左 Shift 回到 Rime 时，Rime 仍可能保持 ASCII 模式，因此看起来切回了输入法，实际仍在输入英文。

前文的配置将左右 Shift 都交给 Fcitx5，同时将 Rime 对单按 Shift 的动作设为 `noop`。这样两个键操作的是同一层状态。

### 根据现象定位问题

| 现象 | 优先检查 |
| --- | --- |
| 所有应用都无法调出中文输入 | Fcitx5 是否运行、输入法组是否包含 Rime、方案是否部署成功 |
| 只有某个应用不能输入 | 该应用实际使用的显示后端和输入法接入路径 |
| 候选能生成，但候选框不显示或位置不对 | 预编辑与文字提交是否正常，再检查候选窗口和光标位置传递 |
| 普通词能输入，新加短语不出现 | 当前方案、对应短语文件、Tab 分隔、触发编码和重新部署 |
| 切回 Rime 后仍在输入英文 | Rime 是否还处于 ASCII 模式 |
| 普通输入正常，只有 AI 联想没结果 | AI 扩展的触发键、激活配置和模型后端 |

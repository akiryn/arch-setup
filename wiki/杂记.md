#  知道一个aur包名怎么查看到其PGKBUILD？
1. 通过 AUR 官网查看https://aur.archlinux.org/packages/包名
2. 使用yay或paru
直接在终端输出该包的 `PKGBUILD`，无需安装软件包。
```bash
yay -Gp google-chrome
```
将构建文件下载到当前目录，然后查看：
```bash
yay -G google-chrome
```
3. 使用 Git 获取
```bash
git clone https://aur.archlinux.org/google-chrome.git
```

# Fontconfig
**Fontconfig 是 Linux 上负责发现和匹配字体的库。** 应用告诉它想用什么字体，比如 `Adwaita Sans`，Fontconfig 会从系统和用户安装的字体中找出合适的字体文件。它还支持别名和回退规则，比如把通用名称 `sans-serif` 匹配到具体字体，或为主字体缺少的中文字符提供候选字体。

`monospace` 是一个**通用字体名**。运行 `fc-match monospace`，实际匹配到的可能是 `Noto Sans Mono`。同类通用名称还有 `sans-serif` 和 `serif`。


|命令|用途|
|---|---|
|`fc-match 'Adwaita Sans'`|查看请求 Adwaita Sans 时，首选的实际字体|
|`fc-match 'sans-serif:lang=zh-cn'`|查看简体中文无衬线字体的匹配结果|
|`fc-match -s 'Adwaita Sans'`|查看按匹配顺序排列的候选字体|
|`fc-list : family`|列出 Fontconfig 能发现的字体家族|

# a
Shorin 的 Niri 有两层差异。**`SHORiN-KiWATA/niri` 是修改过的合成器，`shorin-niri` 是一套桌面预设**。你遇到的「单按 `Mod` 打开网格总览」同时用到了两层：预设写了快捷键，合成器必须认识对应的按键语法和动作。

我用三个基准对照：官方最新稳定版 **`v26.04`（`8ed0da4`）**、官方开发分支 **`main`（`9955d92`）**、Shorin 合成器 **`main`（`4cdb17e`）**。桌面预设按你本机仓库的 **`db87226`** 分析。你本机运行的 Niri 报告为 `26.04 (8ed0da4)`，对应官方稳定版。固定版本的完整源码差异可以逐文件展开。[官方稳定版](https://github.com/niri-wm/niri/releases/tag/v26.04) · [稳定版与 Shorin 的完整差异](https://github.com/niri-wm/niri/compare/8ed0da4...SHORiN-KiWATA:4cdb17e) · [官方开发分支与 Shorin 的差异](https://github.com/niri-wm/niri/compare/9955d92...SHORiN-KiWATA:4cdb17e)

## 1. 合成器功能的差异

Shorin 分支相对 `v26.04` 向前 488 个提交，比较接口列出 222 个变更文件。这里面混有后来合入的官方开发提交，不能把这 488 个提交都算成 Shorin 自己新增的功能。下表按行为归纳，逐文件和逐行变化以上面的固定提交比较为准。

|功能|官方稳定版 `v26.04`|Shorin 分支|
|---|---|---|
|普通总览|提供 `toggle-overview`，缩小工作区，让你查看和切换窗口|保留普通总览，另有独立的网格总览|
|网格总览|本机动作列表没有 `toggle-grid-overview`|把窗口排列成网格。支持键盘导航、点击聚焦、拖放、浮动窗口布局、选中高亮，以及进入和退出动画|
|网格多显示器与规则|无对应的网格配置|可配置网格作用范围、间距和外边距，也可通过规则排除特定窗口。预设使用 `grid-all-monitors true`|
|单修饰键与松键动作|本机 `binds` 拒绝裸 `Mod`|可将裸 `Mod` 作为触发键，并用 `release` 在松开时执行动作。**这部分也已进入官方开发分支**，而网格总览是另一项功能|
|窗口最小化|无 Shorin 这套最小化和网格恢复机制|支持 `minimize-window`、网格中识别与恢复最小化窗口，并处理占位、动画和最小化状态上报|
|全屏放大镜|无预设所用的 `magnifier {}` 和 `adjust-magnifier-zoom`|可开关放大镜、调倍率、移动放大区域，并在放大期间使用专属按键。预设倍率为 `3`，`track-cursor false`|
|摇鼠标放大指针|无预设所用的 `cursor { shake-to-enlarge { … } }`|快速摇动鼠标可暂时放大指针。预设设为倍率 `7`、保持时间 `1500ms`|
|屏幕取色|已有 `niri msg pick-color`|修改取色交互，显示局部放大视图，方便点准像素。**复制颜色到剪贴板**仍是预设中 `niri-pick` 脚本的职责|
|截图输出|提供交互区域、窗口和显示器截图|分支历史还加入了截图写到标准输出的支持。预设中的提示音、Satty 编辑和剪贴板操作由外部命令完成|
|屏幕共享|通过桌面 portal 与 PipeWire 提供屏幕共享|分支加入内置 portal 后端和原生共享来源选择器，并修改了选择器的实时背景和录制交互|
|全屏鼠标约束|无预设所用的 `confine-mouse-to-fullscreen`|可将指针限制在全屏窗口范围内，另有浮动窗口聚焦时的处理|
|自动化输入|无 Shorin 的 `agent` 接口|提供通过 IPC 操作应用的第二个输入 seat。源码包含专用应用 socket、窗口捕获、键鼠操作和 AT-SPI 控件查询|
|布局与渲染细节|使用稳定版的布局与渲染实现|另有列移除后的补位、取消最大化的位置恢复、动画重排、多 GPU 捕获及虚拟机渲染等改动。具体适用条件要看对应提交|

网格总览、摇鼠标放大指针和全屏放大镜可以对照作者的功能演示。关于裸 `Mod` 的归属，Shorin 合并提交明确写了从上游合入 `press/release` 和裸修饰键触发。因此，**「官方稳定版没有」和「只有 Shorin 才有」是两个不同的判断**。[作者功能演示](https://github.com/niri-wm/niri/discussions/4028) · [Shorin 合成器源码](https://github.com/SHORiN-KiWATA/niri/tree/4cdb17e) · [官方开发分支对照](https://github.com/niri-wm/niri/compare/v26.04...9955d92)

## 2. 默认配置逐文件有什么不同

官方稳定版的示例以一份 `default-config.kdl` 展示默认设置。Shorin 桌面预设把设置拆成多份文件，并加入了完整桌面所需的程序和规则。[官方默认配置源码](https://github.com/niri-wm/niri/blob/v26.04/resources/default-config.kdl) · [Shorin 预设配置入口](/home/y/Downloads/shorin-niri/dotfiles/.config/niri/config.kdl)

|文件|Shorin 预设的实际改动|
|---|---|
|`config.kdl`|导入快捷键、规则、输出、动画、布局、模糊和颜色配置。设置中文优先语言环境、Fcitx、Qt 的 GTK 平台主题、Breeze 光标、键盘重复速度、平坦鼠标加速和触摸板自然滚动。配置最近窗口预览、普通总览、网格总览和放大镜，并隐藏启动快捷键提示|
|`binds.kdl`|大幅改写按键布局，加入中文或双语菜单标题、应用启动、取色、截图编辑、音效、Waybar 管理、主题切换、网格总览和最小化。重点重映射见下表|
|`layout.kdl`|单独维护列宽预设、默认列宽、边距、聚焦环、边框、阴影和屏幕保留区。预设默认列宽是工作区宽度的 `0.5`|
|`rule.kdl`|按 App ID 或标题设置特定窗口的尺寸、浮动方式和外观。例如临时终端、工具窗口和普通平铺窗口可走不同规则|
|`animations.kdl`|分别配置工作区切换、横向移动、窗口开关、移动、缩放、截图 UI、总览和聚焦环动画|
|`blur.kdl`|为窗口、layer surface 和弹出菜单配置模糊及背景效果。是否能加载某项语法要看合成器版本|
|`colors.kdl`|单独管理最近窗口等界面的高亮颜色。配色脚本和模板负责把壁纸颜色应用到桌面组件|
|`output.kdl`、`output-example.kdl`|将显示器设置与示例单独维护。实际生效的是配置入口所包含的文件|
|`debug.kdl`|为调试设置提供单独入口|
|`agent.kdl`|提供 Shorin 自动化 seat 的配置及窗口规则。当前预设入口没有直接包含这份文件|
|`hyprlock.conf`、`scripts/`|锁屏样式和桌面辅助程序，例如快捷键菜单、窗口信息复制、取色和电源菜单|

Shorin 还配置了壁纸守护进程、Waybar、Mako、剪贴板历史、SwayOSD、截图音效和 `niriusd` 等启动项。你前面问过的 `quicksave`、`nirius`、Matugen 和 Waybar 切换都属于这一层。把对应快捷键移到官方 Niri，仍要另外满足程序、脚本路径和运行环境要求。[启动项 (line 187)](/home/y/Downloads/shorin-niri/dotfiles/.config/niri/config.kdl:187) · [预设快捷键](/home/y/Downloads/shorin-niri/dotfiles/.config/niri/binds.kdl)

## 3. 会直接改变操作习惯的快捷键

下面比较的是**官方示例配置与 Shorin 仓库预设**。你 `~/.config/niri/` 中的个人配置可能已有不同绑定。

|操作|官方 `v26.04` 默认示例|Shorin 预设|
|---|---|---|
|快捷键帮助|`Mod+Shift+/` 打开内置帮助|同一键调用自定义菜单脚本|
|启动器|`Mod+D` 启动 Fuzzel|`Mod+D` 把窗口向右移入或移出列|

|滚轮导航|`Mod+滚轮` 切工作区，`Mod+Shift+滚轮` 横向聚焦|交换这两组操作，`Ctrl` 对应的移动操作也随之调整|

回到你本机的报错，仓库这段配置需要两个独立能力：

```
Mod hotkey-overlay-title="切换网格总览界面 toggle grid overview" {
    release { toggle-grid-overview; }
}
```

外层要求能**单独绑定 `Mod` 并在松键时触发**，内层要求有 **`toggle-grid-overview`**。你的 `v26.04` 两处都无法按这段配置工作。改回多行只能恢复 KDL 语法。即便换到支持裸修饰键和 `release` 的官方开发版本，也还要单独核对网格动作。你当前的 `Mod+O { toggle-overview; }` 则调用的是官方稳定版已有的普通总览。
